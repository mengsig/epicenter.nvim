1. INTRODUCTION                                        *epicenter-introduction*

epicenter.nvim drives NavGraph, a code-graph engine, from inside Neovim: fuzzy
symbol search, repo-wide grep, a live blast radius panel with ripples in the
code, a hover card of callers, fan-in/fan-out badges, and diff impact against
a git ref, callers and callees, the call path between two symbols, a live
outline, hot spots, unused symbols, and a graph export - all live on every
keystroke.

The engine runs as `navgraph lsp`, an LSP server over stdio speaking the
standard subset plus custom `navgraph/*` methods. One server per workspace
root. Open buffers are sent as overlays, so answers include unsaved edits.

Every request is asynchronous and cancellable, and a response superseded by a
newer keystroke is dropped rather than painted. The preview's file read is
the one blocking part of the UI path, capped at 20,000 lines scanned; past
that it says so instead of freezing (see |epicenter-search|).

2. INSTALLATION                                        *epicenter-installation*

Install the plugin with any plugin manager, then get the binary: >

    :Epicenter install
    :checkhealth epicenter
<
With lazy.nvim, wire the installer to the build hook: >lua

    {
      "mengsig/epicenter.nvim",
      build = function() require("epicenter").install({ wait = true }) end,
      opts = {},
    }
<
Calling |epicenter.setup()| is optional; the defaults apply on their own.

                                                          *epicenter.install()*
require("epicenter").install({opts})
    Downloads a release with `gh` when it is authenticated, otherwise clones
    and builds with `zig`. Reports exactly which tool is missing when neither
    route is available. Installs to `stdpath("data")/epicenter/bin/navgraph`.

    Fully asynchronous by default - a `build =`/`run =` hook must pass
    `{ wait = true }` (or a custom millisecond timeout), since a plugin
    manager treats the hook function `returning` as the step being done.
    With `wait`, returns `ok, err_or_path` once installation actually
    finishes instead of while it is still downloading or building.

The binary is looked up in this order:
    1. `navgraph.path` from |epicenter.setup()|
    2. `navgraph` on `$PATH`
    3. `stdpath("data")/epicenter/bin/navgraph`

                                                                  *:Epicenter*

    its own arguments. With no subcommand, runs `status`.

                                                         *epicenter-quickfix*
QUICKFIX AND LOCATION LIST

Every subcommand that produces rows takes `--qf` or `--loc`: the result set
goes to the quickfix list (or this window's location list) instead of staying
in a panel, and the list opens ready for `:cnext`. >

    :Epicenter blast --qf
    :Epicenter callers M.handle --loc
<
Inside any panel or palette the same two lists are one key away: `<C-q>` sends
the rows to the quickfix list, `<C-l>` to the location list. `<Tab>` toggles a
row into a multi-selection first - with a selection, `<C-q>` sends only those
rows; with none, it sends every row on screen.

Each entry carries `file`, `line`, `col` and the row's own text, so the list
reads the way the panel did.

    {

          lua = "busted %f",

      },
      theme = { accent = "auto" },
      tour = { offer = true },
      ui = {
        border = "rounded",
        height = 0.8,
        icons = "auto",

<
navgraph.path        Explicit binary path. When set but not executable this is
                     an error, not a silent fallback.
navgraph.args        Extra arguments appended to `navgraph lsp`.
navgraph.repo        Source repository for |epicenter.install()|. A release
                     download is SHA256-verified against the release's
                     `SHA256SUMS`; a source build has no artifact to check
                     against, so `navgraph.repo` plus a local `zig build` is
                     its trust root.
navgraph.install_ref Git ref to build from on the source route.

lsp.auto_start       Start a server automatically for indexed buffers.
lsp.root_markers     Checked in order at each level walking upward from the
                     buffer; the first hit is the workspace root, else the cwd.
lsp.fallback_only    Hide navgraph's `definition`, `references`, `hover` and
                     `documentSymbol` on buffers that already have another
                     language server offering them, so `gd`, `gr` and `K`
                     never return duplicates. Set false to keep them all.
lsp.init_options     Passed verbatim as LSP `initializationOptions`.
lsp.restart          Crash recovery: at most `max` restarts, waiting
                     `backoff_ms[n]` before each. After that a notice names the
                     log path.

ui.width, ui.height  Fractions of the editor when <= 1, absolute cells when >1.
ui.max_width,        Upper bounds in cells.
ui.max_height
ui.icons             "auto" (nerd glyphs when |g:have_nerd_font| is set),
                     "nerd", or "ascii".
ui.preview           Show a preview pane when the editor is wide enough.

animate              Master motion switch. |g:epicenter_reduce_motion| also
                     turns motion off, and wins over this.
animation.*          Durations in ms. `frame_budget_ms` drops the next frame
                     after any frame that cost more than it.

blast.*              Blast panel defaults; see |epicenter-blast|.
ripples              Mark the impacted lines in the code while a blast panel
                     is open. `false` turns the marks off.
hover.*              Hover card; see |epicenter-blast|.
badges               "cursor" (badge the definition the cursor is inside),
                     "all" (badge every definition in the buffer), or `false`.
explore.debounce_ms  Quiet time after |EpicenterIndexed| before the explorer
                     re-fetches its open rows.
path.step_ms         Time each step of the path ladder takes to draw.
outline.width        Sidebar width in cells.
outline.debounce_ms  Quiet time before the outline follows the cursor.
hot.limit            Most hot spots listed.
hot.bar_width        Width in cells of the fan-in bar.
unused.limit         Most unused symbols listed.

keymaps              `false`, or a table with `prefix`.
log.level            "error", "warn", "info", "debug" or "trace".
log.file             Defaults to `stdpath("state")/epicenter.log`.

                                                  *g:epicenter_reduce_motion*
Set `vim.g.epicenter_reduce_motion = true` to disable every animation for the
session. Widgets land on exactly the same final state.

6. HIGHLIGHTS                                            *epicenter-highlights*

Groups are derived at runtime from the active colourscheme (`Normal`,
`NormalFloat`, `FloatBorder`, `Comment`, `Title`, `Function`, `Special`,
`DiagnosticInfo`) and re-derived on `ColorScheme`. Override any of them via
`highlights` in |epicenter.setup()|.

    EpicenterNormal     panel background and text
    EpicenterBorder     panel border
    EpicenterTitle      panel title
    EpicenterAccent     the one accent colour
    EpicenterMatch      matched characters in a result
    EpicenterMuted      secondary text (paths, hints)
    EpicenterCount      fan-in and other counts
    EpicenterInfo       informational notices
    EpicenterSelection  the selected row
    EpicenterPrompt     the prompt line
    EpicenterHint       footer hints
    EpicenterRange      the highlighted range in a preview
    EpicenterRipple1    ripple ring 1, the strongest grade (see |epicenter-ripples|)
    EpicenterRipple2    ripple ring 2
    EpicenterRipple3    ripple ring 3 and deeper

`theme.accent` decides where `EpicenterAccent` itself comes from: `"auto"`
(default, `Function`/`Title`), `"mono"` (drops it - the flattest palette), or
a literal `"#rrggbb"` / highlight group name to borrow `fg` from.

==============================================================================
7. HEALTH                                                    *epicenter-health*

`:checkhealth epicenter` reports, in order: this plugin's version, the Neovim
version (and whether it is 0.11+), the resolved navgraph binary and the
version it reports, the negotiated protocol version of every running server
(and any restarts it has needed), whether nerd-font glyphs are in use, the
state of the keymaps, and the log file's path.

The keymap check names two things it can see: `keymaps.prefix` mapped on its
own - which makes every epicenter key wait out 'timeoutlen' before it fires -
and any of its own mappings another mapping now owns. It cannot see a mapping
`setup()` itself replaced: |vim.keymap.set()| overwrites silently.

                                                       *epicenter-first-run*
On the first buffer navgraph would index in a session where no binary can be
resolved, one notice says so and points at `:Epicenter install`. It is said
once per session, not once per buffer. Every error notice names the log file,
which `:Epicenter log` opens.

8. EVENTS                                                    *epicenter-events*

                                                          *EpicenterIndexed*
Fired after every (re)index, mirrored from the server's `navgraph/indexed`
notification. `data` carries `reason`, `files`, `symbols`, `edges`, `ms` and

    vim.api.nvim_create_autocmd("User", {
      pattern = "EpicenterIndexed",
      callback = function(ev) print(ev.data.symbols) end,

<

    local events = require("epicenter.events")
    local unsubscribe = events.on(events.INDEXED, function(payload) end)
<

SEARCH                                                        *epicenter-search*

                                                          *:Epicenter-search*
:Epicenter search                                              *<leader>es*
    Fuzzy symbol search across the project, re-queried on every keystroke
    (debounced 40ms). Rows show the kind icon, the qualified name with the
    matched characters lit, `file:line`, and the fan-in count.

    `navgraph/search` items carry `matches`: 0-based byte indices into the
    symbol's `qualified` name (not the row, and not 1-based like `line`).

                                                            *:Epicenter-grep*
:Epicenter grep                                                *<leader>eg*
    Repo-wide text search over the server's in-memory sources, so unsaved
    edits are included. Same palette, different source.

                                                      *epicenter-palette-modes*
It is ONE palette in three modes, and `<C-space>` cycles them without losing
what you have typed:

    symbols         fuzzy over every definition
    grep            the same query as text, over the whole repo
    references      the use sites of what matches, grouped by the definition
                    they sit inside

Both commands open the same palette - `:Epicenter search` starts in symbols,
`:Epicenter grep` in grep - and the box renames itself as you cycle.

                                                        *epicenter-frecency*
Symbols you have jumped to before rank first, per project. Each pick is sent
back as `search.recent` on the next query, and the list is remembered under
`stdpath("state")` - never in the project itself.

Keys inside the palette:

    <CR>            jump to the result, pushing the jumplist
    <C-t>           open in a new tab
    <C-v>           open in a vertical split
    <C-x>           open in a split
    <C-n>, <Down>   next result
    <C-p>, <Up>     previous result
    j, k            next / previous result (normal mode)
    <C-space>       symbols -> grep -> references
    <C-r>           grep: toggle regex
    <C-k>           symbols/references: cycle the kind filter
                    (all -> functions -> types -> values)
    <Tab>           add / remove this row from the selection
    <C-q>, <C-l>    send the rows to the quickfix / location list
    <C-y>           yank `file:line`
    ?               toggle the key help (normal mode)
    <Esc>, q        close

Options: >lua

    search = { debounce_ms = 40, limit = 50 },
    grep   = { debounce_ms = 60, limit = 200 },
<
==============================================================================
BLAST                                                         *epicenter-blast*

                                                           *:Epicenter-blast*
:Epicenter blast [{symbol}]                            *epicenter-<leader>ee*
    What breaks if this symbol changes. Without an argument the target is the
    symbol under the cursor; with one, the symbol of that name.

    The header names the root and carries the summary chips - symbols, files,
    tests and the deepest ring reached - followed by the query mode. The body
    is one section per depth ring, each grouped by file. A row is the kind
    icon, the qualified name, `file:line`, a muted `?` when the edge was
    resolved by name alone, and a `test` tag on a test definition.

    The panel is live: every reindex re-queries (debounced) and the result is
    diffed against what is on screen. Arriving rows flash the accent, departing
    rows dim and then leave, and the chips count across. The panel is never
    rebuilt underneath you.

Keys inside the panel: the same as every other results panel, except `<CR>`
stays open and `o` is a toggle rather than a one-shot peek - a stated choice,
since this one is a persistent, live-updating query rather than a picker.

    <CR>            jump to the symbol (panel stays open)
    <C-v>, <C-t>    open in a vertical split / a new tab
    o               toggle a peek at it without leaving the panel
    y               yank `file:line`
    +, -            deeper / shallower - the chip names both depths
    d               flip callers <-> callees
    t               cycle the tests scope (with -> without -> only)
    s               toggle strict resolution (drops heuristic edges)
    f               follow the cursor: the panel re-targets as you move
                    (debounced, `blast.follow_debounce_ms`) and hands focus
                    back to the code
    j, k, gg, G     move
    /               filter by name
    ?               toggle the key help
    q, <Esc>        close

Options: >lua

    blast = {
      depth = 2,                  -- rings requested
      max_depth = 6,              -- upper bound for `+`
      direction = "callers",      -- "callers" | "callees"
      tests = "with",             -- "with" | "without" | "only"
      strict = false,             -- drop name-resolved edges
      layout = "float",           -- "float" | "vsplit"
      follow_debounce_ms = 80,
      realtime_debounce_ms = 150,
    },
    ripples = true,
<
                                                           *:Epicenter-hover*
:Epicenter hover                                       *epicenter-<leader>ek*
    A card for the symbol under the cursor: kind and signature (syntax
    highlighted), `N callers` / `M callees`, `file:line-endLine`, the doc
    comment above the definition, and the top callers.

    The card does not take focus. Press `<leader>ek` (or `K`) again to step
    into it: `j`/`k` move through the callers, `<CR>` jumps to one, `q` or
    `<Esc>` closes. Moving the cursor dismisses it.

                                                                *epicenter-K*
    On a buffer where navgraph is the hover provider - which under
    `lsp.fallback_only` means no other language server offers one - `K` opens
    this card. Where another server does answer hover, `K` stays that server's
    key. `keymaps = false` installs neither.

Options: >lua

    hover = {
      callers = 5,      -- top callers listed on the card
      max_width = 80,
    },
<
                                                            *:Epicenter-diff*
:Epicenter diff [{ref}]                                *epicenter-<leader>ed*
    The same panel, rooted on every symbol the working tree changed rather
    than on one symbol. The header reads `changes vs {ref}` ("HEAD" by
    default) and the chips lead with how many symbols changed. Every panel key
    works here too.

    It refreshes on reindex like any panel, and navgraph indexes your open
    buffers as overlays - so an edit you have not saved is already in the
    answer.

                                                          *epicenter-ripples*
RIPPLES

While a panel is open every impacted definition line is marked in the code
itself: a sign-column glyph and a tinted line, graded by ring, strongest at
ring 1. The marks are dropped when the panel closes. `ripples = false` turns
them off.

    EpicenterRipple1    ring 1, the strongest grade
    EpicenterRipple2    ring 2
    EpicenterRipple3    ring 3 and deeper

These three are derived from `EpicenterAccent` over the editor background
(not the float background - they land in ordinary windows) and re-derived on
`ColorScheme`.

                                                           *epicenter-badges*
BADGES

`badges` puts the fan-in and fan-out of a definition at the end of its line as
muted virtual text, revealed left to right:

    function M.handle_request(method, path)      <- 1  -> 2

    "cursor"   the definition the cursor is inside, refreshed on |CursorHold|
    "all"      every definition in the buffer
    false      no badges

Both modes read one `navgraph/outline` per buffer, cached and refreshed on
every reindex - so the counts follow your unsaved edits.

==============================================================================
EXPLORE                                                      *epicenter-explore*

                                                        *:Epicenter-callers*
:Epicenter callers [symbol]                                    *<leader>ec*
    A tree of who calls the symbol under the cursor. Pass {symbol} to root the
    tree at a name instead. Only the first level is fetched; `l` asks the
    server for the next one, so the panel opens in one request whatever the
    size of the graph.

                                                        *:Epicenter-callees*
:Epicenter callees [symbol]                                    *<leader>eC*
    The same tree in the other direction: what the symbol calls.

Rows carry the kind icon, the qualified name, `file:line`, and:

    2x              the edge has more than one call site
    ?               a heuristic edge - resolved by trailing name, not by an
                    exact qualified match
    recursive       the node is already open further up this branch, so the
                    tree stops rather than looping
    ~ ext           the muted group holding calls that resolve to nothing in
                    the index (external or unknown)

Keys inside the panel:

    j, k, gg, G     move
    l               expand (fetching the level on first open)
    h               collapse
    <CR>            jump to the symbol, pushing the jumplist
    <C-v>, <C-t>    open in a vertical split / a new tab
    o               peek at the definition without leaving the panel
    y               yank `file:line`
    <Tab>           add / remove the row from the selection
    <C-q>, <C-l>    send the rows to the quickfix / location list
    r               toggle reference edges
    s               toggle strict mode (drops the `?` edges)
    t               cycle the test scope (with -> without -> only)
    /               filter by name
    +, -            grow / shrink
    <, >            narrower / wider
    <C-arrow>       move
    ?               toggle the key help (normal mode)
    q, <Esc>        close

The open rows are re-fetched on |EpicenterIndexed|, debounced and repainted
once as a batch, so a burst of edits does not flicker or fan out one request
per row.

`+`/`-`/`<`/`>`/`<C-arrow>` are shared by every panel built on this shared
kit (a float, with no fixed `box` of its own - the dashboards excepted): a
resize is remembered per PANEL TYPE (not per project) under
`stdpath("state")`, so `:Epicenter callers` reopens at the size you last left
it, across a restart. A vsplit panel (e.g. |epicenter-outline|) keeps its own
window's height/width instead - there is nothing to remember, it is already
whatever you left it at. |epicenter-blast| owns its window separately and
already spends `+`/`-` on query depth, so it does not have this.

Options: >lua

    explore = { debounce_ms = 100 },
<

PEEK                                                           *epicenter-peek*

                                                           *:Epicenter-peek*
:Epicenter peek                                                *<leader>eP*
    The definition under the cursor, in a float that does NOT take focus:
    read it and keep typing. Off a name it falls back to the definition whose
    body the cursor sits in.

    <CR>            go to what the peek is showing
    q               dismiss it

    Both keys are borrowed from the buffer underneath while the float is up
    and handed back when it goes. Moving the cursor, entering insert mode or
    leaving the buffer dismisses it too.

    The same component answers `o` inside every panel - there it takes focus,
    because the panel already holds the cursor.

CRUMBS                                                       *epicenter-crumbs*

Two one-line components for your own statusline and winbar. Both read a cache
on every redraw and ask the server at most once per line the cursor reaches;
with no server running for the project both are empty and nothing is sent.

                                                    *epicenter.breadcrumbs()*
require("epicenter").breadcrumbs()
    The enclosing chain of the cursor's line, outermost first, joined by
    `crumbs.separator`. For a winbar: >lua

        vim.wo.winbar = "%{v:lua.require'epicenter'.breadcrumbs()}"
<
    Set `crumbs.winbar = true` to have epicenter install exactly that on every
    code window - it never overwrites a winbar you set yourself.

                                                     *epicenter.statusline()*
require("epicenter").statusline()
    The fan-in/fan-out of whatever the cursor is inside, e.g. `⌁ 12 ← · 4 →`.
    Drop it into lualine, heirline, or `statusline` directly: >lua

        vim.o.statusline = "%f %{v:lua.require'epicenter'.statusline()}"
<
                                                         *:Epicenter-crumbs*
:Epicenter crumbs
    Turns the breadcrumb winbar on or off in this window, without editing the
    config for a one-off look.

Against a server older than protocol 1.1 the chain is the enclosing definition
alone - what that server can answer, rather than an invented chain.

Options: >lua

    crumbs = { debounce_ms = 120, separator = " › ", winbar = false },
<
==============================================================================
HIERARCHY                                                 *epicenter-hierarchy*

Both panels ride the standard LSP call- and type-hierarchy methods the v1.1
protocol adds, so any editor gets them - not just this one. Against a server
that does not announce them the panel says so and sends nothing.

                                                     *:Epicenter-hierarchy*
:Epicenter hierarchy [incoming|outgoing]                       *<leader>eH*
    Who calls the symbol under the cursor, as a tree. `incoming` by default;
    `d` flips the whole tree to what it calls instead. Only the first level is
    fetched - `l` asks for the next one - so the panel opens in one request
    whatever the size of the graph.

                                                         *:Epicenter-types*
:Epicenter types                                               *<leader>eT*
    The supertypes, subtypes, implementors and users of the type under the
    cursor, in four groups. A supertype expands upward and a subtype
    downward; implementors and users are locations, so they are leaves - a
    user row also carries how it uses the type (`as param`, `as field`, ...).
    Users comes from the custom `navgraph/types`, not the standard LSP
    methods the other three groups use - it is only asked for once the
    server announces that method; an older server still shows the other
    three.

Rows carry the kind icon, the qualified name, `file:line`, and:

    3x              the caller reaches it from more than one call site
    ?               a heuristic edge - resolved by trailing name, not by an
                    exact qualified match
    recursive       the definition is already open further up this branch

Keys are the shared panel keys (|epicenter-explore| lists them), plus:

    l, h            expand (fetching the level) / collapse
    d               call hierarchy: flip incoming <-> outgoing

==============================================================================
CONTEXT                                                     *epicenter-context*

The two questions an editing agent asks about code: everything about one
symbol, and what a line belongs to. Both need protocol 1.1; against an older
server the command says so and sends nothing.

                                                       *:Epicenter-context*
:Epicenter context [symbol] [--budget {n}]                     *<leader>ey*
    Yanks one symbol's context bundle to the `+` register as compact markdown:
    signature, doc, body, callers, callees, types and tests, each with its
    `file:line`. Without {symbol} the cursor's own definition is used. A toast
    reports the token estimate.

    The server trims the bundle to {n} tokens (2000 by default) by dropping
    bodies first, then tests, then types, then callees; a trimmed bundle says
    so, in the markdown and in the toast.

    With `--qf` (or `--loc`) the bundle's members also land in the quickfix
    list, so the same set is walkable with `:cnext`.

                                                         *:Epicenter-where*
:Epicenter where [{file}:{line}]
    The definition enclosing a line, with the breadcrumb chain that reaches
    it. Without an argument, the cursor's line. Paste a frame off a stack
    trace or a diff header to find out what it is inside of: >

        :Epicenter where app/services/order_service.py:112
<
==============================================================================
TESTS                                                         *epicenter-tests*

                                                         *:Epicenter-tests*
:Epicenter tests [symbol]                                      *<leader>et*
    Every test from which the symbol under the cursor is reachable - the
    coverage walk run backwards - grouped by the file it lives in. Needs
    protocol 1.1.

    Rows carry the test's name, its `file:line`, and `dN`: how many calls
    away the target is. `d1` is a direct test; anything deeper reached it
    through other definitions, which is worth knowing before trusting it.

    Keys are the shared panel keys (|epicenter-explore| lists them), plus:

    l, h            expand / collapse a file
    r               run the test under the cursor

                                                   *epicenter-tests-runner*
`r` runs one test through a per-language command template. `%f` is the test's
file, `%s` its own name; the command runs in the project root through your
`shell`, and its output streams into a scratch split. Nothing blocks. >

    require("epicenter").setup({
      tests = {
        runner = {
          python = "pytest %f::%s",
          go = "go test -run %s ./...",
          -- add a language by naming it
          elixir = "mix test %f",
        },
      },
    })
<
A language with no template says so and runs nothing.

IMPACT                                                       *epicenter-impact*

What the working change reaches, without being asked. On every reindex - and
only while something is actually unsaved - epicenter asks `navgraph/impact`
and marks each impacted definition where it lives: a sign in the gutter and a
calm note at the end of its line, graded by how many calls away it is.

With nothing unsaved there is no working change, so no request is sent and
every mark comes down. Needs protocol 1.1.

                                                        *:Epicenter-impact*
:Epicenter impact                                              *<leader>ei*
    The blast panel, rooted at the changed hunks rather than at one symbol.
    Every key the blast panel has (|epicenter-blast|) works here.

                                                         *epicenter-review*
                                                        *:Epicenter-review*
:Epicenter review [export]                                     *<leader>ea*
    The same impact as a review list: rows grouped by changed hunk, each
    impacted definition with its `file:line`, how many calls away it is, and
    `?` when the edge was resolved by name rather than exactly.

    a               approve this row - it turns to a faint check, here and
                    on the marker in the code
    A               approve every impacted definition in this row's file
    u               unapprove this row
    <CR>, o         jump to it / peek at it without leaving the panel

    `:Epicenter review export` copies the whole list to the clipboard as a
    markdown checklist, for a pull-request description. `e` does the same
    from inside the panel.

    Approvals live under `stdpath("state")`, per project, and are keyed by the
    definition AND the hash of its source: edit that definition and it comes
    back unreviewed, while everything you already looked at stays ticked.

                                                    *epicenter-impact-line*
The progress fits a statusline: >

    require("epicenter").impact()   -- "impact 3/12 reviewed", or ""
<
`impact = { inline = false }` keeps the panel and the statusline but marks
nothing in the code; `impact = { enabled = false }` turns the whole ambient
surface off, request included.

10. EXTENDING                                            *epicenter-extending*

A feature is one file under `lua/epicenter/features/` returning a spec, plus
one `require` line in `lua/epicenter/features/init.lua`: >lua

    local M = {}
    M.name = "hot"
    M.summary = "Hot spots ranked by fan-in"
    M.options = { hot = { limit = 20 } }
    M.option_rules = { positive = { ["hot.limit"] = true } }
    M.commands = {
      { name = "hot", desc = "Hot spots", run = function(ctx) end },
    }
    M.keymaps = { { suffix = "h", command = "hot", desc = "Epicenter: hot" } }
    return M
<
`option_rules` is how a feature validates its own options at |epicenter.setup()|
time: `variants` lists the types a path accepts, `enums` the values, `positive`
the paths that must be a positive number. A feature may only rule on paths
rooted at an option key it owns.

A feature that needs to watch the session - autocmds, buffer-local keys - adds
`setup = function(cfg) ... end`. It runs at the end of |epicenter.setup()| and
must be idempotent, because a second `setup()` calls it again.

`lua/epicenter/registry.lua` collects the specs; `:Epicenter` completion, the
keymap installer, `:checkhealth` and the config defaults all iterate it. Two
features claiming the same subcommand or option key is a hard error.

Feature modules must not require `epicenter.config` at file scope - config
builds its defaults from the registry, so that would be a cycle.

The UI kit is the public contract:
`epicenter.ui.window`, `.animate`, `.easing`, `.theme`, `.icons`, `.list`,
`.tree`, `.prompt`, `.preview`, `.toast`, `.palette`, `.panel`. Server access
goes through `epicenter.client`, which has a helper for every `navgraph/*`
method and returns a handle with `:cancel()`.

Add a documentation section per feature with its own `*epicenter-<name>*` tag,
so two features being written in parallel never edit the same region. Feature
sections carry no number - only the CONTENTS list and this section are
numbered - so a new one is a pure addition, never a renumbering of the rest.
